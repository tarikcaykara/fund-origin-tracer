# fund-origin-tracer

Open-source crypto fund-flow tracer (Ethereum, Polygon, Arbitrum, TRON) for compliance/AML, fraud/risk and security/IR teams. Bun workspace, strict TypeScript end to end.

## Gotchas

- **Tronscan returns rows newest-first and ignores `sort`.** Forward listings therefore use a bounded window (`afterTs − 5 s` … `+30 d`, narrowed to `+1 d` when incomplete) and are re-sorted ascending client-side. The base URL is `https://apilist.tronscanapi.com/api` with header `TRON-PRO-API-KEY`; keyless requests get HTTP 429.
- **Tronscan `transaction-info` returns `{}` for unknown hashes** (HTTP 200); the provider maps that to `not_found`.
- **Etherscan errors arrive as HTTP 200 envelopes.** Rate limits and "free API access is not supported" are `status:"0"` bodies, not HTTP errors; classify the body, never cache error envelopes. Only genuine empty results are cached. A result is cached only after it passes the schema the caller parses it with (each `call`'s `ttl` checks it), so a malformed answer is fetched again next time, never replayed from the cache. JSON-RPC quantities (`Quantity`, `providers/etherscan.ts`) need at least one hex digit: `BigInt("0x")` throws a `SyntaxError`, which the engine would treat as `internal_error` and fail the whole run, while a `provider_error` fails only one seed or edge.
- **The free Etherscan tier covers chainid 1, 137 and 42161 only.** BSC (56), Base (8453) and OP are paid-only and return `Free API access is not supported`; they are out of scope (`chain_requires_paid_plan` is fatal).
- **Etherscan `txlistinternal&txhash=` rows have no `hash` field**; the transaction is already known, so do not require it.
- **Requests time out, and a long `Retry-After` is not waited out.** `fetchTransport` (`packages/core/src/infra/transport.ts`) aborts a request, body included, after `REQUEST_TIMEOUT_MS` (30 s; `TransportRequest.timeoutMs` overrides it, the OFAC download asks for 90 s) and throws a retryable `network_error`; an abort of the caller's signal passes through with the caller's reason. `withRetry` (`infra/retry.ts`) gives up at once when `Retry-After` exceeds `MAX_RETRY_AFTER_SEC` (60): a `rate_limited` error passes through unchanged (Tronscan's `KeyExhaustedError` must still retire its key), any other code becomes `rate_limited`. The trace's timer is cleared when `runTrace` returns, so `executeRun` (`apps/server/src/execute.ts`) bounds `analyze` (the convergence follow-up) by the rest of `timeoutSec`, aborting with reason `"timeout"`.
- **The OFAC SDN XML is about 29 MB and the URL redirects**: the transport must follow redirects. The currency tag does not identify the chain; classify addresses by format. `parseSdnXml` finds entries with `indexOf` (`entryBodies`), never a lazy regex such as `<sdnEntry>([\s\S]*?)</sdnEntry>`: that rescans to the end for every unclosed tag, which is quadratic (CodeQL `js/polynomial-redos`) and blocks the server while it parses. Never record the full XML in fixtures (`ofac.json` holds the parsed snapshot; `packages/core/test/fixtures/ofac/sdn-fragment.xml` is a five-entry capture for the parser test). Snapshots are version 2 (`{version, fetchedAt, entries, evm, tron}`); version 1 address-only snapshots (the committed demo `ofac.json` files) still load and get the constant `OFAC SDN` label.
- **An OFAC response counts as a download only if it is a complete SDN list with addresses.** `OfacSource.load` (`packages/core/src/labels/ofac.ts`) requires `<sdnList` and `</sdnList>` in the body and at least one EVM or TRON address. Any other HTTP 200 body (a maintenance page, a format change, a cut-off download) fails like an HTTP error: the previous snapshot stays in use (empty only when none exists), the warning is `ofac_unavailable`, and the KV snapshot is not overwritten. Test stubs that need a loaded list serve `FAKE_SDN_XML` (`apps/server/test/helpers/fake-etherscan.ts`), never `<sdnList/>`.
- **The OFAC refresh is a `setTimeout` chain, not an interval.** `scheduleOfacRefresh` (`apps/server/src/ofac-refresh.ts`, started by `startServer`) waits until the loaded snapshot is `OFAC_REFRESH_HOURS` old, measured from its `fetchedAt`. A fixed interval would skip every other refresh, because `OfacSource.load` finds a snapshot downloaded a few seconds after the previous tick still fresh. While no snapshot within that window is loaded, it retries after 1, 2, 5, then every 15 minutes. Tests inject `now` and `setTimer`.
- **Recording and replay must both use engine concurrency 1 and a fresh `MemoryCacheStore`.** Otherwise request order and cache hits differ and replay raises `fixture_miss`. Request keys sort query params and drop `apikey`; headers are never part of the key.
- **Price by contract, never by symbol.** A spoofed "USDT" must not be valued at $1; only `CANONICAL_TOKENS` entries with `stable: true` are 1:1 (TRON USDC and USDD are looked up).
- **Guessed token decimals are never priced.** Explorer and contract decimals are accepted only in 0–255 (`MAX_TOKEN_DECIMALS`, `chains.ts`); anything else becomes 18 with `decimalsGuessed: true`, and `transferUsd` (`providers/types.ts`), used by the trace and the convergence follow-up, returns null for such transfers.
- **Cycle detection is per path**, not global: the same address reached by two different branches is not a cycle. Existing transfers are linked, not re-expanded.
- **Identical transfers in one explorer response are separate events.** The listings carry no event index (Etherscan `tokentx` rows have no `logIndex`, `txlistinternal` `traceId`s repeat across distinct calls and `&txhash=` rows have none, Tronscan has none), so `numberRepeats` (`packages/core/src/schema.ts`) sets `Transfer.repeat` (1, 2, …) on the 2nd, 3rd, … equal copy and `transferId` appends it. Providers number each listing page on its own (a row repeated on the next page of a shifted listing is the same event and the engine dedupes it) and a transaction as a whole. Never change the id of an unrepeated transfer: stored results link by edge id (`edgeIdFor` hashes `transferId`) when they are expanded.
- **TRON swap-through only works for seed transactions** (listings are direction-filtered, so the opposite swap leg is not visible).
- **`maxEdges` counts expansions started**, reserved before the first await so the limit is exact under concurrency.
- **`paused` is a live overlay status**, never persisted; `GET /api/runs?status=paused` is rejected.
- **Docker: `env_file: .env` overrides the image `ENV`.** A dev `.env` with `DATA_DIR=./data`, `PORT=3100` or `HOST=127.0.0.1` (as `.env.example` ships) would break the volume, the port mapping or the bind, so `docker-compose.yml` sets `PORT`, `DATA_DIR` and `HOST` under `environment:` (which wins over `env_file`). The server runs from TypeScript sources; there is no server build step, only `apps/web/dist`.
- **The server binds loopback, checks `Host` and sends a CSP.** `Bun.serve` listens on `HOST` (default `127.0.0.1`). `refuseForeignHost` (`apps/server/src/app.ts`) answers every route with `403 host_not_allowed` unless the Host name is `localhost`, `127.0.0.1`, `[::1]` or in `ALLOWED_HOSTS` (DNS rebinding); IP literals are not allowed automatically, so LAN access needs both `HOST` and `ALLOWED_HOSTS`. `secureHeaders` is registered before it, so refusals and errors get the headers too: a CSP without inline scripts (`style-src` keeps `'unsafe-inline'` for Radix and sonner), `frame-ancestors 'none'`, `X-Frame-Options: DENY`, no HSTS. The pre-paint theme script therefore lives in `apps/web/public/theme-init.js`, never inline in `index.html`, and the Vite dev proxy targets `127.0.0.1:3000` (`localhost` may resolve to `::1`, where nothing listens). `app.request` in tests sends no Host header; the check then uses the request URL's host.
- **Transfer timestamps are unix seconds.** `Transfer.timestamp`, `TxDetail.timestamp` and `ExchangeTouchpoint.timestamp` are seconds; `AnalysisResult.startedAt`/`finishedAt` and run `createdAt` are ISO strings. Format transfers with `formatTimestamp`/`formatCompactTimestamp` (`apps/web/src/format.ts`); `new Date(timestamp)` renders 1970.
- **Modals return focus themselves.** Radix `Dialog` refocuses only a `DialogTrigger`, so the ⌘K palette (`apps/web/src/components/command-palette.tsx`: three openers, no trigger) keeps the element focused at open (`onOpenAutoFocus`) and refocuses it on close, except after a pick; the ☰ menu's Search focuses ☰ first, because the menu unmounts with it. `ModalLayer` (`components/modal-layer.tsx`: phone detail sheet, Full graph) refocuses its opener, or `returnFocus()` when the opener is gone: the phone sheet then focuses the active workspace tab (after a palette pick, or a Flags / Linked button whose `selectInGraph` switched to the graph tab).
- **Text reaches 4.5:1 on every surface in both themes.** `--faint-foreground` (about 3:1) is for placeholders, disabled text and decoration only, as the design system says; secondary text is `text-muted-foreground`, never faint or `opacity-*`. The dark `--destructive` is a light red (`#ff6b5e`) so `text-destructive` passes on dark surfaces, which makes the dark `--destructive-foreground` dark. Phone tables that would scroll sideways become stacked rows (Exposure "By category").
- **Demo runs cannot be expanded.** `RunManager.expand` (`apps/server/src/runs.ts`) refuses runs with a `demo` id (`409 demo_run_not_expandable`): a continuation would use the live providers, SQLite cache, label registry and OFAC set, mixing live data into a recorded replay. `DEMO_ONLY=true` refuses every expand with `409 demo_only`.
- **`DEMO_ONLY` instances are read-only for visitors.** Every visitor is anonymous, so the `refuseOnDemoOnly` middleware (`apps/server/src/app.ts`) answers `PATCH`/`DELETE /api/runs/:id` and `POST /api/runs/:id/{pause,resume,cancel}` with `403 demo_only` before validation or lookup (unknown ids cannot be probed). Non-demo rows already in `DATA_DIR` stay hidden: `RunManager.visibleSummary` (`runs.ts`) makes reads, the event stream, exports and expand answer `404 not_found`, and `InvestigationListQuery.demoOnly` (`db.ts`) filters the list and `totalAll`. The web hides Rename, Notes, Pause, Resume, Cancel and Delete when `health.demoOnly` is true. `RunManager.pause/resume/cancel/patch/remove` stay unguarded for tests and shutdown.
- **Demo replays are bounded and share their scenario.** `RunManager` (`apps/server/src/runs.ts`) admits at most `maxDemoRuns` (8) replays at once (`429 too_many_runs`, checked after the scenario load in the same synchronous block as `register`, so concurrent starts cannot overshoot) and loads each scenario once (`RunManager.scenario`: recording, OFAC set and `LabelRegistry`, shared by every replay; d1/d3 recordings are ~12.5 MB of JSON). Unknown ids and failed loads are not cached. On `DEMO_ONLY`, `startDemo` calls `Investigations.pruneDemoRuns(maxStoredDemoRuns)` (100) so demo rows cannot fill the disk. The smoke runs at most 5 demos at once, below the cap.
- **Bodies, idle connections and event streams are bounded.** `bodyLimit` on `/api/*` (`MAX_BODY_BYTES` = 128 KB, `413 payload_too_large`, before `zValidator` parses) and `Bun.serve` `maxRequestBodySize` (1 MB) for every route. `Bun.serve` keeps Bun's idle timeout (10 s, checked on a 4 s tick); the SSE route turns it off for its own request with `c.env.timeout(c.req.raw, 0)` (`c.env` is the Bun server; undefined under `app.request`), because keepalives come every 15 s. `createApp` caps open streams at 10 per run and 100 in total (`429 too_many_streams`, taken before `streamSSE`, released in its `finally`). `RunEventListener` gets a memoized `json()` so an event is serialized once for all subscribers; call it synchronously.
- **An expansion does not own the run status.** `runTrace` reports the continuation's own status. `executeRun` (`statusAfterExpand` in `apps/server/src/execute.ts`) replaces it, before `analyze`, with the status of the merged graph: `timed_out`/`failed` continuations win; otherwise the previous status stands, and `timed_out`/`cancelled` turn `completed` once no `timeout`/`cancelled` edge is left. Flags, risk level and the stored row all follow.
- **A thrown or interrupted expansion keeps no result.** The `launch` catch (`apps/server/src/runs.ts`) stores `failed` with `result_json` and `risk_level` cleared, and boot recovery (`Investigations.markInterrupted`, `apps/server/src/db.ts`) clears them for every `running` row. The pre-expansion result is never replayed or exported as the current one; the stream follows the no-result path (`snapshot → error → done failed`).
- **Expansion counters are run totals.** The engine counts a continuation from zero; `executeRun` adds `previous.stats` to every `progress` it emits (as `mergeStats` does at the end), so `progress`, `snapshot.stats` and `result.stats` never go backwards. `RunManager.expand` emits an `expansion` event (`edgeId`, `maxDepth`, `base` = the totals before) and replays it after `snapshot`; the panel shows `progress − base`. Budgets (`maxEdges`, `timeoutSec`) are per expansion. The web expands `PANEL_EXPAND_DEPTH` (1) hop per click; the API default stays `DEFAULT_EXPAND_DEPTH` (3). The cost hint comes from `listingCalls` (`chains.ts`), kept honest by provider tests.
- **`provisional` events are live-only.** `RunManager` (`apps/server/src/runs.ts`) runs `analyzeProvisional` over its live edge mirror at most once per `provisionalIntervalMs` (1 s) when edges changed, on pause and at expand start; it replays the latest one after `snapshot`, stops at `result` and never persists it. No explorer calls: convergences lack `otherCounterparties`, and `incomplete_trace` ignores the (not yet existing) run outcome. The workspace tabs render `DerivedAnalysis` (`schema.ts`), which both the provisional analysis and `AnalysisResult` satisfy.
- **Playwright files are `*.smoke.ts`, never `*.spec.ts`.** `bun test` also collects `*.spec.ts`, so the browser smoke runs only through `bun run smoke` (Playwright Test under Node). Bun loads `.env` into every `bun` process, so the smoke server runs with `--no-env-file` and gets every `EnvSchema` variable from `webServer.env` (a new key goes there too); otherwise a developer's `EXPLORER_MAX_PAGES` would change the request sequence and break replay with `fixture_miss`.

## Hard rules

1. Code, comments, docs, commits and UI are in English.
2. `packages/core/src` imports nothing from `bun`, `bun:*` or `node:*`; only web-standard globals. Env, files and the clock are injected.
3. One result schema: `packages/core/src/schema.ts`. Server, CLI and web import it; never duplicate result or event types.
4. Every bundled label carries a public `source` URL that was opened and verified.
5. Never commit API keys, `.env` or recorded keys. Fixtures strip `apikey`; headers are never recorded.
6. Never push. The owner pushes. After v1, work goes through `<type>/<issue-number>-<slug>` branches and PRs, squash-merged by the owner.

## Conventions

- Conventional Commits in English (`feat`, `fix`, `refactor`, `test`, `docs`, `build`, `ci`, `chore`, `perf`). No `Co-Authored-By` lines.
- Gate before every commit: `bun run check && bun run typecheck && bun test`. Biome (2.6+) formats Markdown by default; `biome.json` turns that off (`markdown.formatter.enabled: false`) so the hand-formatted docs stay as written. `biome.json` takes its `$schema` from the installed package (`./node_modules/@biomejs/biome/configuration_schema.json`), so a Biome bump never leaves a stale schema version behind; run `biome migrate --write` only when a new Biome version renames or removes a config option.
- Explicit `.ts` import extensions and `import type`.
- Update `README.md`, `CLAUDE.md` and `.env.example` in the same commit as any behaviour or config change.

## Testing policy

- Every bug fix starts with a regression test that fails before the fix, in the layer where the bug lives: `packages/core/test/`, `apps/server/test/`, `apps/cli/test/` or `apps/web/test/` (web modules).
- Core logic (engine, analysis, providers, parsers) is written test-first; tests stay offline (captures in `packages/core/test/fixtures/`, fakes in `test/helpers/`).
- The browser smoke (`apps/web/smoke/`) grows only for new or changed user flows, or for bugs that reproduce only in a browser; it stays a smoke, not a full e2e suite.
- Each issue's Acceptance names the test that proves each item.

## Workflow

- Work is tracked in GitHub milestones (`Phase N — Name`, each with a "Done when:" description) and issues, one issue per plan step until v1.
- Issue titles use the commit style (`feat(core): …`); bodies carry Scope, an Acceptance checklist and the planned commit message.
- Commits reference their issue with a `Refs #N` footer, or `Closes #N` on the commit that finishes it. The owner pushes and closes issues; never close one yourself.
- After v1, branches are `<type>/<issue-number>-<slug>` (`<type>/<slug>` when there is no issue) and the PR body says `Closes #N`. A milestone is a release (`vX.Y.Z — Theme`, with a "Done when:" description); work not planned for soon stays out of milestones.
- `master` is protected by the repository ruleset "Protect master" (GitHub settings, not a file): pull request required with 0 approvals, required status checks `check` and `smoke` from GitHub Actions, branches need not be up to date, force pushes and deletion blocked. Repository admins may bypass on pull requests only, so even the owner cannot push to `master` directly.
